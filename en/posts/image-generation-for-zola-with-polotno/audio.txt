Ich liebe Podcasts und höre wirklich viel, deshalb habe ich auf meinem Android Smartphone Antennapod installiert. Das ist eigentlich mein absoluter Lieblings Podcatcher, den ich ab und zu auch als Feed Reader benutze. Dabei ist mir aufgefallen, dass ganz einfache RSS Feeds oft keine Coverbilder haben, und genau das wollte ich für meinen eigenen Feed ändern. Außerdem brauchte ich sowieso Vorschaubilder für die sozialen Medien. Jeder Blogbeitrag braucht ja ein ansprechendes Titelbild, um in sozialen Medien, in RSS Feeds und auf der Website selbst Aufmerksamkeit zu erregen. Aber das manuelle Erstellen individueller Bilder für jeden einzelnen Artikel ist einfach zeitaufwändig und kostet mich unglaublich viel Überwindung.

Ich habe mich daher entschieden, diesen Prozess komplett zu automatisieren. Ich wollte ein Skript, das aus den Metadaten meiner Blogbeiträge automatisch verschiedene Bilder für unterschiedliche Plattformen generiert. Das Design soll einheitlich sein, aber die Elemente sollen individuell auf den Inhalt des jeweiligen Artikels abgestimmt sein.

Ich zeig dir heute mal, wie ich das technisch gelöst habe. Im Grunde nutze ich eine Kombination aus mehreren Technologien. Zola verwende ich als statischen Site Generator für den Blog und in diesem Fall auch als Server für den RSS Feed. Für die Ausführung nutze ich Bun, das ist eine JavaScript Runtime, die einfach schneller ist als Node js. Die eigentliche Programmlogik habe ich in TypeScript geschrieben und für die programmatische Bildgenerierung setze ich Polotno ein. Als Datenquelle dienen mir die RSS Feeds, aus denen ich die Beitragsinformationen ziehe.

Das System generiert für jeden Blogbeitrag vier verschiedene Bildformate. Da gibt es ein Vorschaubild für soziale Medien, zwei verschiedene Formate für Instagram und ein Bild für die RSS Reader. Zusätzlich werden alle Bilder automatisch für die verschiedenen Sprachversionen meines Blogs erstellt.

Um das Ganze zu starten, habe ich mir ein kleines Beispiel in Form eines Bash Skripts vorbereitet, das den gesamten Prozess steuert. Zuerst wechselt das Skript in das Verzeichnis mit den Skripten und startet dann den Zola Server im Hintergrund auf dem Port eintausendeinhundertvierunddreißig. Dann wartet das System fünf Sekunden, bis der Server vollständig hochgefahren ist, und führt anschließend das TypeScript Skript mit Bun aus. Sobald die Bilder generiert wurden, wird der Zola Server wieder beendet. Zum Schluss werden alle Änderungen in das Git Repository eingelesen, hinzugefügt, mit einem Zeitstempel committet und hochgeladen.

Jetzt schauen wir uns mal den Kern der Lösung an, also das TypeScript Skript, das die eigentliche Arbeit erledigt. Ich habe da eine Hauptfunktion gebaut, die den gesamten Prozess steuert. Zuerst wird der RSS Feed abgerufen. Das Skript parst die XML Daten und extrahiert alle relevanten Informationen wie den Titel der Beiträge, das Veröffentlichungsdatum, das ich direkt in ein schönes deutsches Format bringe, sowie die URLs der Beiträge. Auch die Kurzbeschreibungen werden ausgelesen, wobei ich sie auf maximal fünfhundert Zeichen kürze und alle HTML Elemente entferne, damit der Text im Bild sauber aussieht.

Eine wirklich clevere Funktion ist die automatische Farbgenerierung. Ich habe eine Funktion geschrieben, die den Titel des Artikels nimmt und daraus einen sogenannten Hash Wert erzeugt. Dieser wird dann in einen Hex Farbcodes umgewandelt. So erhält jeder Artikel eine einzigartige, aber konsistente Farbgebung, die bei jedem Durchlauf gleich bleibt.

Für die Bilder selbst nutze ich JSON Vorlagen, die ich im Polotno Studio erstellt habe. Das Skript passt diese Vorlagen für jeden Artikel dynamisch an. Der Hintergrund bekommt einen individuellen Farbverlauf, dann wird der Titel eingefügt, gefolgt vom Datum und meinem Namen als Autor. Zusätzlich wird ein Ausschnitt des Inhalts als Hintergrundtext verwendet. Man muss hier nur darauf achten, dass die Ebenen in der JSON Vorlage genau so benannt sind, wie sie im Skript angesprochen werden.

Die finalen Bilder werden dann über die Polotno Schnittstelle in JPEG Bilder umgewandelt. Ich lasse das Skript für jede Sprachversion und jedes Format einzeln laufen, wobei ich kleine Pausen von einer Sekunde einbaue. Die fertigen Bilder werden dann in einer strukturierten Verzeichnisbaum gespeichert, sortiert nach Artikelname, Sprache und Bildtyp.

Damit Zola diese generierten Bilder dann auch korrekt nutzen kann, habe ich in der Template Konfiguration hinterlegt, dass das System automatisch nach dem Vorschaubild im entsprechenden Sprachordner sucht. So werden die Bilder für Open Graph und Twitter Cards automatisch richtig zugewiesen, sofern ein Pfad für die Seite existiert.

Die Vorteile dieser Automatisierung sind echt riesig. Erstens habe ich ein konsistentes Design, was die Markenidentität stärkt, falls ich überhaupt eine hätte. Zweitens gibt es trotzdem diesen individuellen Touch durch die Farben und die Inhalte. Vor allem spare ich aber extrem viel Zeit, weil die Bildgenerierung einfach passiert, bevor der Artikel veröffentlicht wird, indem ich nur das Deployment Skript ausführe. Auch die Mehrsprachigkeit ist damit ohne zusätzlichen Aufwand gelöst und durch die Git Integration werden alle Änderungen sofort live geschaltet.

Im Fazit kann ich sagen, dass ich mit dieser Kombination aus Zola, Bun, TypeScript und Polotno eine elegante Lösung gefunden habe, um meinen Workflow zu verbessern. Die automatische Bildgenerierung sorgt dafür, dass jeder Artikel visuell ansprechend präsentiert wird, ohne dass ich selbst Hand anlegen muss. Das Ganze ist super flexibel und man kann es leicht anpassen, indem man die Vorlagen ändert oder neue Formate hinzufügt. Falls du diesen Ansatz für deinen eigenen Blog verwenden möchtest, musst du dir nur einen eigenen Polotno API Key besorgen und die Vorlagen an dein eigenes Design anpassen.

Das war es für heute, ich hoffe, das war hilfreich für euch und wir hören uns beim nächsten Mal.
